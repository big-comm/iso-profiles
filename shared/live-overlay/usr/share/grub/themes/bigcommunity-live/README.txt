BigCommunity Live - GRUB theme

Every edition ships this theme: bigcommunity/<edition>/live-overlay/usr is a
link to shared/live-overlay/usr.

Visual: the language of comm-welcome. The snowy owl of the "Olhar" wallpaper
looks at the screen from the left; the menu sits over the dark part of the
photo. Adwaita Sans (the GNOME font), accent #c9a2ff, and the selected row in
the Welcome's purple (#8b3ff0 at 34 %) with a lilac frame and a soft neon glow.
Single-colour line icons after the Lucide set (ISC licence).

Sources: every file here except ter-u22b.pf2 and the progress_* slice geometry
is generated by shared/grub-assets/theme/build_theme.py (owl photo:
olhar.jpg in the same folder). Edit the script, rerun it and commit the output;
the ISO build only copies this folder. Fonts:
- adwaita-sans-semibold-18.pf2: menu rows and countdown. Built from the
  system Adwaita Sans variable font at weight 600 (SIL OFL 1.1). Latin, Greek
  and Cyrillic only; Hebrew and CJK fall back to unicode.pf2.
- ter-u22b.pf2: terminal font for the editor and command line (Terminus).
cfg/grub.cfg loads unicode.pf2, then Adwaita Sans (only if the file exists),
then Terminus.

GRUB rules this theme depends on (checked in grub-mkrescue + QEMU, BIOS and
OVMF UEFI, from 640x480 to 3840x2160 including 16:10, 3:2 and 21:9, and in
grub-core/gfxmenu):

- PF2 fonts are 1-bit: GRUB cannot antialias them. Only the menu rows and
  the "%ds" countdown use the PF2 font; the wordmark (header.png) and the key
  hints (hints.png) are antialiased bitmaps.
- GRUB picks a font by the name stored inside the PF2 file ("Adwaita Sans
  SemiBold Regular 18"). Any other name in theme.txt silently falls back to
  a different font. tests/test_grub_contracts.py checks this.
- GRUB never scales an image down, and "50%-N" only centres when N is half
  the real width. width/height of every "+ image" are the PNG's own size;
  the tests check this too.
- desktop-image-scale-method "crop" with left/top alignment scales the
  background to cover the screen and keeps its left part. The background is
  4267x1200 (32:9): a 16:9 composition plus plain shaded dark on the right.
  Every screen up to 32:9 (4:3, 16:10, 16:9, 21:9) is covered by height, so
  the owl keeps its place and size; a 16:9 background was covered by width on
  21:9 screens, which enlarged the owl under the menu.
- GRUB asks for 1024x768, then 800x600, then the firmware's mode (variable.cfg).
  At 640x480, only reached when the firmware has neither, the menu still
  works but is cramped. A firmware that offers only a 4K mode shows small
  text: GRUB draws fonts and images at their pixel size.
- GRUB offsets each row's text by the padding of its pixmap. Only the
  selected row has a visible pixmap (select_*, 14 px slices: 5 px of glow and
  9 px of frame), so item_*.png is a fully transparent copy with the same
  slices; without it the selected row drops 14 px onto the next. Rows are
  28 px + 16 px spacing.
- Scrollbar: scrollbar_slice must be "center". "east" draws the bar inside the
  right padding of the menu box, and with no menu_pixmap_style that padding is
  0, so the bar disappears. scrollbar_width must be at least the frame's
  left + right slices (3 + 3 px), or GRUB disables the bar.
- Rows shown = (menu height + spacing - 2 x item_padding - selection pads)
  / (item_height + spacing), from gui_list.c. Height 48 % gives 10 rows at
  1080p and 7 at 1024x768: the UEFI root menu (1-7, with "Detect EFI
  bootloaders" and the EFI memory test) and menu 3 fit exactly. The language
  selector (30 rows) and menu 3.2 (11 rows) scroll. At 800x600 the menu shows
  5 rows and scrolls.
- GRUB forces a minimum height on progress_bar (font height, ~28px), even
  with a smaller height, no text and pixmaps, and draws the highlight inside
  the track's content area. Hence the 6 px bar:
    * progress_bar_*.png (track) uses 1 px wide by 11 px tall slices and
      paints only the MIDDLE ROW of the 9-slice, which GRUB squeezes from
      11 px to height-22 = 6 px. Slices can have independent width and height,
      and that matters: GRUB draws the fill offset by the track pads, so a wide
      (11 px) slice pushed the fill 11 px inwards;
    * progress_highlight_*.png uses 2 px slices and is drawn at y=11 with the
      same 6 px.
  Equal slices in both files misalign the bars or fatten them to 28 px.
  build_theme.py only recolours these slices; it never resizes them.
- @TIMEOUT_NOTIFICATION_*@ only works in progress_bar. In a label the counter
  is "%ds", which GRUB fills with the number and needs no translation. Theme
  label text is never translated by GRUB, so the key hints stay in English.
